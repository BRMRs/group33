# C 版：长者少操作，照护者承接异常

调研日期：2026-10-16。用途：一次性设计验证，不是正式 Android 规格。以下是公开产品资料与设计指导，不是本应用已经通过长者可用性测试的证明。

## 参考产品与实际采用的做法

这些资料支持设计方向；照片识别率、默认字号是否足够、三个按钮是否容易混淆，仍需目标长者使用自己的药盒与手机验证。

## 页面与组件

- 主页：一条当前结论。待提醒时只显示下一次时间；确认后不继续展示药盒；延后后显示准确的再次提醒时间；求助后提供直接联系入口。
- 闹钟页：当前提醒时间、真实药盒照片及必要数量、三个直接操作。无药名长列表、规格文本、逐药选择、同步提示或“点照片看大图”文案。
- 照片：1 盒单图；3 盒横向总览；6 盒两行总览。320px 或较大字体下增加行数以避免横向溢出。点照片只放大，返回保留原任务；不代表选中或服用。
- 主操作最少 76 CSS px，高对比实心蓝色；延后与求助最少 68 CSS px，间距 14px。CSS px 不是 Android dp/sp，这不是对实机触控的认证。
- 默认正文 21px、主按钮约 26px，主状态约 33px；颜色不单独承担含义。三个操作均有可见文字、辅助图标和按压反馈。
- 用原生按钮的 click 而非 touchstart 提交，避免滚动刚接触屏幕就触发动作。提交立即离开可重复提交的闹钟页，不增加例行确认层。
- 页面变化聚焦主标题；反馈使用独立 status live region。可选浏览器语音仅在评审者启用后播报；其实际声音、读音和平台支持仍需听测。
- 无固定悬浮控件遮挡药盒或操作，长页面只有一个页面滚动区。小屏、六盒或放大字体可能需要滚动，这一点不掩盖。

## 流程及演示参数

默认时间 17:55，原提醒 18:00，两小时响应截止 20:00。

1. 已吃好：对本次整组作自我报告，立即显示“这次吃药已记下”。不是证明吞服；不要求选择具体药物。
2. 延后：整组固定延后十分钟，不因一次延后通知照护者；再次到时回到照片总览。延后不改变原响应截止。如果再过十分钟已到或越过截止，不承诺再次响铃。
3. 求助：不问原因，记录求助并停止重复催药。长者只看到“求助已记下”，不会在未送达时被告知“照护者已收到”。联系按钮只打开演示入口，不拨号。
4. 未回应：服务端模拟基于已知提醒计划在原提醒后 30 分钟生成关注通知；15/30/60 分钟可切换。阈值是演示假设，不是医疗建议或已经批准的服务规则。
5. 已接收延后但长期未完成：到同一关注阈值后提示“长时间延后，尚未确认完成”，不标成主动求助。同一关注事件不随每次推进时间重复生成。
6. 确认迟到达：跟进卡更新为“长者随后已回应”；保留老人操作时间与服务端接收时间。不会把延迟接收误写成延迟服药。
7. 照护者可标记“已联系”；这不替代长者的服药报告，也不自动将事件改为已服药。

## 同步只给照护者看，且不假装知道未知信息

独立模拟手机记录与照护者已接收记录。控制台可断开传输或模拟拒收。

- 长者端不展示 Pending sync、Synced、失败重试或时间戳。
- 照护者端展示已接收的回应、长者操作时间、记录接收时间、最后设备联系时间，以及服务端能知道的接收失败。
- 断开传输后，照护者看不到手机上的新动作，也不能凭空知道手机上有 Pending sync。这里只根据最后联系时间提示信息可能不是最新，并按未回应规则发起跟进。
- 恢复传输后按原始操作顺序接收，原操作时间不变。同一记录接收重试不重复生成求助通知。
- 所有时间由控制台推进；没有真实后台计时器、推送、消息、电话或持久化。刷新即清空。

## 与现有仓库规则的差异

用户本轮明确选择：整组一次确认、无需逐药解释、同步只给照护者看。这是此次原型的优先要求。

现有 UI_DESIGN_DECISION 的两步 Taken、长者端同步反馈，以及当前单 Dose event API，尚未覆盖整组报告、求助事件与服务端未回应关注。本原型不修改正式规则、API、Kotlin 或 XML。服务端模拟只根据已知计划做“未收到回应”监视，不另行生成正式 Dose event，也不声称核实服药。正式实现前需要团队把已验证的产品决策写入相应领域/API文档。

## 本轮浏览器验证

- 18:00 整组延后，18:05 不重弹，18:10 重弹；一次延后通知数为 0。
- 未回应到 18:30 生成一次跟进；再推进时间不重复生成；“已联系”不把服药结果改成 Taken。
- 离线 18:00 确认，18:35 恢复接收；照护者保留操作时间 18:00、接收时间 18:35，并更新先前的未回应跟进。长者页不显示同步状态。
- 求助遇拒收时不虚称已送达；恢复后生成求助通知，接收重试不重复生成；求助后继续推进时间不再反复催药。
- 连续三次延后，到原提醒后 30 分钟才生成一次“长时间延后”关注。
- 19:55 请求延后不承诺 20:05 再响；20:00 结束该提醒。
- 六张不同实拍图全部加载。在 360×800、中文默认字号下，三个操作的底边分别约为 595、677、759px，均在视口内，触控高度 76/68/68px。
- 六盒场景中英文、100%/200% 字体，在 320px/360px 均无横向溢出，三个操作均保留；200% 并不保证一屏容纳。
- 计算得到主按钮白字/蓝底对比约 7.65:1，正文/白底约 14.22:1，延后按钮文字/底色约 10.54:1，求助文字/底色约 7.47:1。次要按钮边框加深后与白色约 3.99:1。没有据此宣称通过完整 WCAG 或实机无障碍认证。

未完成的真实验证：长者本人认药、相似包装、握持与误触、真实语音听测、Android/TalkBack。原型代码仅供评审，不替代这些验证。
