## 1. 适用范围

MedicationReminder（长辈服药提醒）是 CSI301 课程项目。本政策面向自愿参与的成年团队测试者，覆盖测试版的手机号认证、身份选择、配对同意、照片与计划、提醒反馈及必要的同步。测试不提供诊断、处方或紧急救援；提醒、服药报告和连接状态均不证明实际服药。

联调使用虚构药品、用量、计划和不含真实患者信息的照片。请勿上传他人的手机号、病历、处方、身份证件或可识别患者的照片。测试者可以自愿使用自己的手机号验证认证功能；这仍属于个人信息处理，不因“课程测试”或手机号被哈希而变成匿名处理。

## 2. 项目组处理的信息与用途

- **登录和身份**：用于认证的手机号或短信备用流程中主动输入的手机号、认证结果；以及账号 ID、首次选择并由服务端固定的角色、照护者显示名称。服务端验证时会处理供应商确认的号码；候选持久化设计以带密钥的手机号摘要识别账号，不把该摘要称为匿名数据。
- **安装与会话**：安装 ID、会话 ID、认证请求及到期状态、认证凭证、原操作标识和必要的防重放记录。它们用于维持当前身份、隔离账号与安装、恢复原操作和防止重复提交。身份验证不直接授予访问其他长者数据的权限。
- **配对与业务资料**：用户主动创建并经长者同意的关系、虚构药盒照片、药品说明、计划、执行时区，以及提醒动作和服务接收时间。这些信息用于测试已授权照护流程。配对码属于临时授权信息，不用于公开展示测试资料。
- **本机设置及缓存**：语言选择、必要的会话状态、Room 缓存、待同步操作和本地提醒状态，用于离线显示、到点提醒及恢复。具体文件和备份排除范围由发布版本核验，不承诺“所有数据均加密”或“卸载必然清除所有副本”。
- **连接和诊断**：处理请求所需的网络 IP、请求时间、状态及安全错误分类，用于传输、限流和排错。托管平台也会处理连接数据。项目诊断应避免记录完整手机号、认证 proof、访问令牌、配对码、照片和用药正文；最终版本需验证日志配置。

我们不以本测试提供广告投放、出售用户数据、医疗判断或面向用户的商业画像。登录风控 SDK 的数据处理仍需单独披露，不能据此声称“没有第三方 SDK”或“第三方绝不收集标识”。

## 3. 第三方 SDK 与服务

手机号测试候选包含以下组件。仅列入依赖不证明每个字段已实际采集；项目组须对最终 APK、实际供应商方案和网络行为逐项核验，完成最终清单后才启用真实认证。

- **阿里云融合认证 SDK**：提供一键登录和 SDK 短信认证；官方指南列出设备名称、型号和系统版本。号码认证还可能涉及本机号码、运营商和网络相关信息。按认证页面展示的运营商协议及[号码认证隐私政策](https://terms.aliyun.com/legal-agreement/terms/suit_bu1_ali_cloud/suit_bu1_ali_cloud202112211045_86198.html)了解详细处理。
- **短信认证 SDK**：提供发送/验证短信的供应商界面与认证结果。输入的号码和验证行为由该认证链处理；设备名称、型号和系统版本等见[短信认证隐私政策](https://terms.alicdn.com/legal-agreement/terms/privacy_policy_full/20230922101800634/20230922101800634.html)。项目不另建手工发码服务，也不要求测试者向项目组提供验证码或登录 proof。
- **图形认证及其服务提供方**：供应商方案在风控需要时可能显示验证，涉及网络 IP、设备/环境和验证交互信息；具体子服务以最终方案为准。参见[图形认证隐私政策](https://terms.alicdn.com/legal-agreement/terms/privacy_policy_full/20240510173033685/20240510173033685.html)。
- **友盟登录安全组件**：当前候选打包 common 9.5.6、asms 1.8.0，并调用 SDK 关联组件的启用接口，用于登录风险检测和频控。设备标识、硬件和网络数据的实际范围须按版本、权限和方案核实；不能直接把供应商列出的所有可选标识当作本 App 的实际采集清单。参见[友盟隐私政策](https://www.umeng.com/policy.html)。
- **Render 与 Supabase**：既定方案由 Render 托管独立测试服务及静态政策页，Supabase PostgreSQL/私有 Storage 保存结构化业务资料和照片。它们接收相应网络请求并承担经审配置中的处理；新资源、地区和权限尚未全部核验，不能视为已启用。参见[Render 隐私政策](https://render.com/privacy)及[Supabase 隐私政策](https://supabase.com/privacy)。项目自己的最终处理披露不能由平台政策替代。

阿里云融合认证通过其服务主体及运营商提供相关能力；号码、短信、图形及友盟具体主体和下游见各官方政策。正式披露需核对实际接收方，而不能只写一个品牌名称替代全部接收方信息。

## 6. 数据访问与安全

业务资料按当前账号、角色和有效照护关系校验，登录本身不授予跨用户读取。团队配置中的供应商密钥、数据库密码和签名私钥仅由指定配置人员处理，不放入 App、公开仓库或测试日志。真实联调地址使用 HTTPS；本地受控脚本/模拟器的 HTTP 证据不代表云端已具备同等保障。

我们尽量减少测试数据与管理权限，不保证网络或系统绝对安全。如发生信息泄露或误传，请立即停止相关测试并联系项目组；项目组应先控制暴露，再按实际情况及适用要求告知和处理。
