# Persistent business SQL statement budgets

2026-10-31 — XinyanXue / S2, Refs #16 / #14 / #13 / #10. Child of exact Draft98 `a223e6cf1f561d55fdae03ec09353dc88e13493d`. Actual main observed as `b2aeb492a97ea1e17ced4da22972f34cae44ea73`. Independent S2 implementation preserving current Shared/wire/role/schema semantics; no unresolved cross-client fields are invented.

## Behavior

Guarded PostgreSQL pairing/photo/plan/occurrence writes now install a transaction-local five-second statement limit alongside the existing configurable lock timeout. Existing anonymous identity registration/profile writes use that same local statement limit alongside their one-second lock timeout. Current anonymous identity lookup uses a five-second JDBC query timeout. Existing configured connection/socket budgets remain; a socket timeout alone is not a server SQL execution limit. No global PostgreSQL settings, new application configuration, migration or public error code is introduced.

A statement limit bounds each SQL command, not the entire HTTP request, Java work or filesystem/network object IO. The statement limit can expire before a larger configured lock wait; existing SQLSTATE55P03 still maps to busy, while other SQL failures retain their current unavailable mapping. The existing read-only plan snapshot path remains unchanged.

The original database transaction continues to own business writes, versions and immutable receipts. After all business and receipt work, `SET CONSTRAINTS ALL IMMEDIATE` runs pending deferred checks under the statement budget, before final COMMIT, in that same transaction. This follows [PostgreSQL 17 constraint-check timing](https://www.postgresql.org/docs/17/sql-set-constraints.html). Final COMMIT durability/network acknowledgement and rollback are not universally bounded to five seconds by this change. Database-confirmed cancellation before successful commit rolls back partial writes; a confirmed failed photo publication retains its already committed STAGING intent and immutable private object for same-operation recovery. A generic503 or lost COMMIT/HTTP response is not proof that nothing committed. Unknown completion must still reconcile/retry the original operation; do not allocate a replacement key or delete its source. No automatic retries, deletion or cleanup are added.

## Verification

Two real PostgreSQL counterexamples (business transaction budget and identity INSERT trigger checking the current budget) fail on the parent implementation before the SQL limits are added. Those same assertions are retained. The first complete limit-only run passed 277 of 278 cases but failed the new deferred plan constraint budget case: the original COMMIT path did not enforce the intended limit there. That failure is preserved in the external packet. The final implementation adds budgeted precommit deferred validation and two identity deferred-trigger cases rather than weakening the assertion. Eleven new real PostgreSQL cases additionally exercise a slow final pairing receipt insert, a slow Medication update, slow deferred plan constraint checks, slow READY photo receipt publication, slow immediate/deferred first identity INSERT/profile UPDATE, and a real locked identity lookup. They validate bounded failure, original state/role/history preservation, original-key replay, STAGING/object recovery, sanitized identity failures and later read recovery. SQL fixtures use `pg_sleep(30)` or a real table lock in the explicitly configured dedicated loopback practice database. No provider, cloud or real medical data is used.

Reproduce with JDK17/SDK35 and existing local dependency cache: `./gradlew gate1Check test --console=plain`; explicit dedicated local PostgreSQL settings and `./gradlew :server:postgresIntegrationTest --console=plain`. Final validation passed: 747 ordinary report instances (Server 627, Shared 18, Android Debug/Release 51 each), 280 real PostgreSQL cases (269 inherited plus 11 new), Gate1/lint/build/policy and production/test package isolation. Server and both Android variants executed; Shared was UP-TO-DATE with its unchanged report retained. The complete PostgreSQL task executed uncached; the dedicated database was stopped afterward. Exact source hashes and logs are retained in the external delivery packet and PR. Existing tests and assertions are not relaxed.
