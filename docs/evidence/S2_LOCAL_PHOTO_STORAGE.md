# Private local photo object storage prototype

Input: main `64ddd4e26440d60a60f209dd7eb12d102e2a55dd`. Local preparation for #13/T06 and #20/ADR-0006, not a reviewed contract or complete photo service. No new Shared/API/HTTP/configuration.

The private POSIX root is 0700, in an existing trusted parent, controlled exclusively by the service OS account. Stream bytes are counted and hashed into a 0600 private temporary file. Only a complete matching file is forced, made owner-readable and installed with non-replacing createLink on the same local filesystem. Matching identity replays; conflicting data is never overwritten. Reads are bounded by the existing 5,242,880-byte budget and check size/hash before returning bytes. UUID-derived filenames, no caller paths/public URLs, no follow of final symlink/root, owner-only object permissions. The proposed seam does not validate JPEG/PNG or MIME and does not authorize a user; callers must first validate actual input and current business permission.

18 real tests passed with zero failures/errors/skips and cover real synthetic PNG/JPEG, bound/hash/IO failure, private modes, incomplete-write visibility, eight independent adapters with matching/conflicting content, symlink/directory/permission/corrupt targets, same-ID replay, 5MiB boundary, retention without age deletion, separate JVM write/read, and abrupt child halt during partial write. Final full checks passed: 92 tasks, 40 executed / 46 FROM-CACHE / 6 UP-TO-DATE. Raw XML/logs and module totals are preserved in the local delivery evidence.

A crash can leave private .part files; no automatic deletion is exposed. Shared references, live leases, reconciliation and >24h eligibility belong to a later reviewed cleanup transaction. A stored object is not READY or a usable Medication: publish READY+accepted receipt transactionally only after object availability. This prototype has no metadata database, auth/controller, Spring bean, Supabase adapter, migration, deployment or two-device evidence.

Assumptions: local POSIX filesystem with hard links/directory sync; unsupported providers fail without insecure fallback. A trusted single OS account/root is required; no defense against another process with the same privilege replacing roots/files during checks is claimed. Independent JVM tests establish process-lifetime persistence, not machine power-loss/filesystem durability certification, Linux/container portability or the full local cloud-independent scenario. Root creation/operational supervision and JVM memory/concurrent-request budgets still need production review.

JDK references: [Files.createLink](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/nio/file/Files.html#createLink(java.nio.file.Path,java.nio.file.Path)), [FileChannel.force](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/nio/channels/FileChannel.html#force(boolean)). File-system support and durability remain provider-specific.
