# Server plan input validation — local preparation

Refs #14; input main `64ddd4e26440d60a60f209dd7eb12d102e2a55dd`. This is an isolated local candidate, not a branch, PR, human review or completion of #14.

`ReminderPlanInputValidator` validates the existing decoded `ReminderPlanDraft`: at least one unique strictly zero-padded HH:mm value, real four-digit ISO dates, inclusive optional end date not before start, and registered runtime TZDB region/alias identifiers. Exact input order and identifiers are preserved; no trimming, deduplication, sorting, zone replacement or undocumented time-count/date-range limits. An empty end-date string is invalid on the wire; only null/absence is open ended. The form's conversion from empty editor text to null remains C2's responsibility.

Sources: [Shared models](../contracts/SHARED_MODELS.md), [API](../API_CONTRACT.md), D01 and T05 in [test plan](../contracts/CONTRACT_TEST_PLAN.md). The zone membership rule also matches C2's PR #43 implementation at `3aabd17a01bc75bc885781f56212ebec9dd57d18`; that unmerged code is not imported. Named TZDB aliases including UTC are retained, while bare offsets and offset-prefixed IDs are not accepted as region identifiers. Available IDs are determined by the running JDK TZDB; cross-runtime equivalence remains an integration concern.

Diagnostics are private Server `PlanInputViolation` values with field paths and an enum, containing no rejected text. They are not frozen HTTP codes or a new Shared error mapping. The validator has no Spring bean/controller or side effects. It returns errors, not an authorized/saved plan or an immutable validated command; an eventual application service must validate the same stable payload it commits. Required JSON null/type/missing-field checks remain transport responsibilities.

Tests exercise all 1,440 minute values, invalid widths/ranges/whitespace/non-ASCII digits, nonadjacent duplicates, exact order preservation, leap-century cases, equal dates/year transitions, impossible and malformed dates, null/absent/empty end dates via real Jackson decoding, registered/unknown/offset zones, multiple independent diagnostics and DST gap/overlap local times. DST local times are valid draft input; later P0_TIME_V1 resolution and cross-plan overlap must not be replaced by this shape check.

Deferred: Medication text validation, timezone acknowledgement against trusted context, photo readiness, authorization, cross-plan overlap including open-ended ranges/DST, canonical fingerprints, receipts, revision checking, plan/Medication transactions, HTTP/localization mapping, persistence and event generation. Shared/Android/auth/persistence configuration are unchanged. Full validation evidence, actual task/cache modes, logs, XML and checksums are retained with the local delivery packet; no CI or device result is claimed.
