# 长者提醒 UI 基线：照片优先，异常由照护者接手

记录日期：2026-10-16。决策入口：[Issue #23](https://github.com/BRMRs/group33/issues/23)。

发布说明：本结论分支从当前 `main` 建立；既有工程/契约文件正在 [PR #22](https://github.com/BRMRs/group33/pull/22) 中发布。两组变更分开保存，本分支不夹带 #22 的代码，也不直接改写其审查内容。集成时须同步修订旧 `docs/UI_DESIGN_DECISION.md`，不能让两份规范同时被误当现行依据。

本文件汇总项目负责人在原型讨论中确认的产品方向，替代“各人凭聊天印象设计”。不是对现有 C 截图的像素批准，也不是已实现的 Android 规范。涉及旧契约的变更按 [ADR-0008](adr/0008-photo-first-elder-reminders-and-caregiver-handoff.md) 评审后生效；在此之前，受影响实现不得自行选用新旧规则。既有 Accepted ADR/契约仍按工程治理顺序执行。未受影响工作继续。

阅读顺序：本基线 → [结论与证据](evidence/ELDER_PROTOTYPE_FINDINGS.md) → ADR-0008 的迁移门禁 → 所属实现 Issue。原型仅作历史证据，不可复制为正式布局。

## 1. 服务对象与核心任务（用户已确认）

面向能识别自己熟悉的原药盒、取药并服用，但不应承担复杂阅读、手机操作和用药管理的长者。照护者负责设置、核对、异常跟进与记录；不假设所有老人的能力相同，也不宣称覆盖无法独立服药的人群。

核心路径是“到点提醒 → 对照照片把这次的药取齐 → 按既定安排服用 → 一次确认”。适老化不是把复杂表单放大：应减少记忆、推断、选择和纠错负担，同时保留长者主动延后的能力。

照片是识别辅助，不是药品身份、剂量或实际服用的证明。产品不决定漏服后如何补服。界面的三十分钟退出规则是交接规则，不是医学上的安全服药期限。

## 2. 页面信息与操作（用户已确认）

| 场景 | 展示 | 操作 | 不展示/不要求 |
| --- | --- | --- | --- |
| 主页 | 简短当前状态、必要时下次提醒时间；有活跃提醒时可返回该提醒 | 拍药盒；需要时进入当前提醒 | 今日全部药清单、药品管理、通用求助、同步状态、完成率 |
| 单药闹钟 | 一张本人的原药盒照片、计划时间一次、每次用量与确有必要的说明 | 药吃好了；10 分钟后提醒；需要帮助 | 毫克规格作为主要视觉层级、逐药勾选、冗长引导 |
| 多药闹钟 | 本次照片总览，六盒两列三行；照片与用量紧邻、顺序稳定 | 同上，作用于当前整组 | 逐盒下一步、吃了几种/几片选择、按药单独延后、拖动分组 |
| 照片放大 | 完整照片；回到原来的位置 | 返回 | “点击看大图”说明、选中/已服用语义 |
| 已确认 | 简短“已记下”，随后回安静主页 | 拍药盒等日常入口 | 旧药盒再次催服、长者处理同步或反复确认 |
| 延后 | 下次提醒时间；本次原始截止不改变 | 到点恢复同组提醒；未截止时可返回当前提醒 | 用新事件替换旧事件、默认通知求助 |
| 求助/超时交接 | 简短表示本次提醒已结束/求助已记下 | 回主页，保留拍药盒 | 旧药的确认或延后按钮、要求长者补明细、声称离线求助已送达 |
| 拍药盒 | 取景/选择照片 → 预览 → 保存结果 | 拍照、使用照片、重拍、返回 | 药名/剂量录入、自动生成计划、自动替换正在使用的药盒图 |

用量如“1 片”是照护者已确认的显示信息，不是让长者选择的输入。简化界面不能删掉辨别本次用量所必需的信息；照片无法辨别的规格不能只靠颜色猜。名称可作辅助和无障碍标签，但不再承担主要识别任务。

## 3. 状态与照护者闭环（用户已确认；协议迁移见 ADR）

| 触发 | 长者侧 | 照护者侧与关闭条件 |
| --- | --- | --- |
| 药吃好了 | 本地可靠记录后立即简短反馈，阻止重复点击；不增加必经二次确认 | 显示“长者报告已服用”及来源/报告时间/接收时间，不称已验证服用 |
| 10 分钟后提醒 | 整组固定延后十分钟，截止仍从原计划时间计算 | 正常延后不是求助或立即升级事件 |
| 下次延后达到/超过三十分钟截止 | 不承诺下一次闹钟；截止前仍能确认或求助，截止到达统一退出 | 进入未回应跟进；不悄悄缩短十分钟或延长本次窗口 |
| 需要帮助 | 单击记录求助，不问理由、不让逐盒选择；停止本次反复催促 | 进入需联系队列；明确是否收到求助，不能从本地记录推断已投递 |
| 原始提醒三十分钟仍未确认 | 清除本次闹钟与旧服药入口，包括通知动作；重启/重连不重放 | 进入未回应跟进；不直接等同“确定未服用” |
| 设备在独立检测阈值内无消息 | 若仍开机，已缓存的提醒与本地截止仍执行 | 单独“设备失联，请联系”，不等三十分钟；不能判断没电/断网/关机。两分钟只是原型参数 |
| 已联系 | 不要求长者回手机补点 | 状态为“已联系，待补登记”，不能直接关闭 |
| 照护者补登记 | 接管已被设备确认后不再重复提示本次服药 | 已服用／未服用／无法确认三选一；保留实际时间或明确未知、登记人/时间、接收时间；无法确认保留关注 |
| 设备未收到接管 | 不假装远端已强制关闭；仍依本地规则到截止退出 | 明确“设备尚未确认”；恢复连接后应用接管，保留原始动作时间 |
| 延迟报告与补登记冲突 | 不把旧记录再次变成待服药任务 | 保留双方记录与来源，显式标记需核实，不静默覆盖 |
| 中途离开/进程恢复 | 不把退出当已服用；仅在仍有效且未接管时恢复同次状态 | 截止照常计算，不因重新打开延长；已确认/已接管/已截止不重放 |

部分服用、某盒找不到、药没了或不确定：统一走“需要帮助”，由照护者联系了解。长者不再做部分服用表单。已有信息不足时，照护者记录“无法确认”，而不是把整组强行归为全吃/全没吃；必要说明由照护者承担。

设备恢复联系不自动关闭用药问题，补登记也不自动证明设备恢复；两条问题分别关闭。照护者未处理、照护者自身离线或通知未送达时，仍保留待办与新鲜度提示；升级渠道、重试和再通知频率必须在通知协议中明确，不能宣称保证及时发现。

## 4. 照片区与操作区：此次收敛结论

当前 C 的三块全宽按钮过度占用纵向空间，六盒照片仅第一排完整，第二排不完整。**当前比例不通过；“按钮够大”不等于适老化完成。** 两列三行是内容结构，不是允许把下两行藏在滚动区的理由。

默认场景的主要任务是识别药盒，照片应占据主要可用空间，操作保持清楚稳定但不成为页面主体。不规定一个适用于所有手机的百分比，也不把浏览器 px 当 Android dp/sp。优先回收评审工具栏、重复时间/角色标题、说明文字、额外留白、重复卡片内边距与过度装饰；不得靠缩小触控目标、删用量或裁掉药盒来腾空间。

团队建议纳入 #19 的一次性验收目标（尚未实机验证）：

- 目标手机、默认字号、六盒场景以三排完整同屏且每盒可识别为目标；当前仅一排完整的布局不得验收。记录实际屏幕、系统栏、可用高宽和照片实占尺寸，而不只报网格列数。
- 如果六盒同屏与可识别性不能同时满足，明确记为未通过并由共享组件负责人统一解决；不让成员各自缩图、隐藏第三排或改成逐药任务。
- 两层操作区（主操作一行、两个次操作一行）只是减少高度的候选实现，不是本轮新批准的版式；须同时满足中英文、至少 56dp 触控目标、主操作至少 64dp 和明确间隔。禁止为塞进一行截断标签。
- 不假设 200% 字号也能同屏六盒。放大时允许线性页面滚动，不能照片滚动、整页滚动相互套用，不能固定按钮盖住内容；信息与动作都要可达。

### 滚动风险不是“加个滚动提示”就能消除

藏在下方的药可能被当成“不属于这一顿”；老人放下手机取药后可能忘记看到了哪里；滑动结束时照片、用量被切开又会加重辨认。滚动条、小箭头、“共六盒”只能辅助，不能证明长者已查看完整。

默认六盒不以“必须发现并滚到底”作为正常路径。兼容场景确需滚动时，顺序固定、返回保留位置、照片与用量不拆开、尾项完全可见、切换语言/放大照片不丢状态；这些仍不能代替真实识别验证。不得用逐药勾选、强制滑到底、全看过确认或额外解释文字把风险转嫁给长者。

## 5. 共用组件、视觉与文案约束

沿用一个产品的白/冷中性背景、深蓝主色、适度圆角、系统字体与 Material Rounded 图标语言。长者和照护者只在密度、层级和尺度上不同，不各造主题。

| 共用对象 | 统一约束 |
| --- | --- |
| 原药盒照片卡 | 单盒真实照片、完整外观、稳定比例与顺序；不要一图多盒/混规格、反光、过多背景或手写杂物。照护者确认关联及包装变化，不自动替换历史实例 |
| 放大组件 | 点图可看完整原图；返回位置不变，不产生服用选择；缺图/相似包装不可伪造通用药盒代替 |
| 操作区 | 三项顺序、文案、语义跨单药/多药保持一致；主操作深蓝、延后中性、求助温和琥珀；不用强烈红色把常规求助表现为急救 |
| 触控与误触 | 点击抬起才触发、移出可取消、明确按压反馈、热区不重叠、重复点击不产生重复业务；不要求长按/双击/滑动才能完成 |
| 操作反馈 | 本地记录成功才说“已记下”；失败不伪装成功。误报交照护者核实更正，保留来源与历史，不把再确认塞回所有正常路径 |
| 字体/触控 | 长者正文≥18sp、辅助≥16sp、关键状态≥24sp；长者触控目标两个方向均≥56dp，主按钮高≥64dp；照护者≥48×48dp |
| 对比/状态 | 正文对比≥4.5:1、大字≥3:1；文字+图标/形状，不只靠颜色。绿色仅表示明确来源的已报告结果，不把未知/联系成功标绿 |
| 字号/语言 | 默认已足够大且支持系统放大；无长者专属 100%/200% 开关任务。默认跟随系统（中文→简中，否则英文），手动系统/中文/英文设置持久化，切换不改业务状态 |
| 同步展示 | Pending sync / Synced / Sync needs attention 保留为独立数据状态，不出现在长者日常主页/闹钟；照护者看实际可知信息、最后联系/接收时间、陈旧/未知提示 |

“服务已接受”“照护者页面已刷新”“通知已送达”“照护者已读”不同，禁止合成一个成功图标。远端看不到尚未上传的本地队列，不能凭无消息准确断言长者未点击；未知必须如实展示。

统一双语资源建议（正式 key 由共享资源 PR 一次锁定，禁止散落硬编码）：

| 语义 | 简体中文 | English |
| --- | --- | --- |
| 服药提醒标题 | 该吃药了 | Time for your medicines |
| 整组确认 | 药吃好了 | Medicines taken |
| 整组延后 | 10 分钟后提醒 | Remind me in 10 minutes |
| 提醒中求助 | 需要帮助 | I need help |
| 主页照片入口 | 拍药盒 | Photograph a box |
| 简短返回 | 返回 | Back |
| 本地动作记录 | 已记下 | Recorded |
| 照片提交 | 使用照片／重拍 | Use photo / Retake |
| 照护者联系后 | 已联系，待补登记 | Contact made — record outcome |
| 照护者补登记 | 已服用／未服用／无法确认 | Taken / Not taken / Unable to confirm |
| 设备状态 | 设备失联，请联系长者 | Device contact lost — contact the elder |

实际服用时间未知时明确显示“时间不确定 / Time unknown”；不能用补登记时刻填充。用户输入的药名/说明保留原文，不自动翻译。技术性错误映射成本地资源，不直接展示服务端原文。

## 6. 六人协作：一套基线，不是六套设计

| 责任槽位 | 交付/评审边界 | 关联 Issue |
| --- | --- | --- |
| C1 + E | C1 集中提交 token、样式、共用状态与双语资源；E 审查长者尺度/认知负担并实现引用它们的长者组件 | #19 |
| E + C2 | 拍照、预览、重拍、照护者确认及药盒图与计划关联；不从照片自动生成安排 | #13、#14 |
| E + C3 | 统一整组提醒、求助、照护者跟进和补登记映射，不由 UI 猜测业务结果 | #14、#19 |
| S1 + S2 | 提出并评审成员/时间/接管/授权/冲突/通知协议及恢复测试；C2/E/C3 共同核对语义 | #12、#17、#18 |
| 全体，负责人整合 | 引用同一提交版本验收中英文、字体、误触、断网及两设备因果路径 | #21 |

以上是既有角色职责，不是具名指派或审批。成员映射仍由负责人填写 `docs/TEAM_ROSTER.md`，不可因为文档已写而宣布功能 Ready。

共享 token 的确切色值/间距/圆角、组件 API、唯一参考布局在 #19 的一个共享 PR 锁定。未锁定前，不允许功能分支各自决定。通用资源同一时间由一个整合分支修改，其他功能提交具体 key/状态需求；合入后引用共同组件，不复制到各自目录再改。模型/API 只走 #12 的评审，禁止页面私加 wire 字段。

### 每个 UI PR 的最低检查

- [ ] 标明基线版本和共用组件版本；偏离先在 Issue 留理由，不静默改。
- [ ] 同一 PR 含中英文资源，不拼接译文、不硬编码尺寸/颜色、不新增私有主题。
- [ ] 主页无通用求助；单药/多药共用三动作；无逐药选择/强制二次确认/长者同步负担。
- [ ] 默认六盒照片识别与完整性有目标设备证据；当前被截断的 C 截图不是合格证据。
- [ ] 360dp 主验收、320dp 兼容、系统 200% 字体、长文本、灰度、TalkBack 遍历、点击取消与误触检查；无横向溢出/盖住末项。
- [ ] 本地动作、服务接受、照护者查看、通知投递分开；超时/接管/重启不重放；未实现的能力不伪装成成功。
- [ ] 有限跟进与异常测试引用 ADR/契约测试；更改共享含义须相关 Android/Server 审查。

## 7. 收口方式

本轮结束 A/B/C 自由探索，不再扩展原型。保留的工作只有：解决 ADR 列出的协议/交付阶段冲突；一次共用参考组件布局定稿；必要的真实长者识别与误触观察。后两项是验收，不是要求反复挑风格。没有真实观察前，不宣称已证明六盒好认或三按钮不会误点。
